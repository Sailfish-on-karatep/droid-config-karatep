# Without this file jolla-camera has nothing to constrain it and picks the
# largest size the Android HAL advertises -- 3840x2160 on the rear camera,
# 3264x1836 on the front. Both cameras will happily *capture* at those sizes,
# but nothing on karatep can encode them. /vendor/etc/media_codecs.xml, which is
# what MediaCodec actually enforces, caps the hardware encoder at
#
#   <MediaCodec name="OMX.qcom.video.encoder.avc" type="video/avc">
#       <Limit name="size" min="96x96" max="1920x1088" />
#
# and the Codec2 software fallback is no better: c2.android.avc.encoder allows
# max="2048x2048" with block-count 1-8192, against the 240x135 = 32400 blocks
# 2160p needs, so it returns -EINVAL. droidcamsrc -- which encodes internally
# via DroidMediaRecorder, so the failure is inside the camera stack rather than
# downstream of it -- then hits "DroidMediaRecorder: Cannot create codec" and
# the buffer queue logs "Client wasn't able to handle a received frame" forever.
# That is the dark viewfinder the moment record is pressed. Capping video at
# 1080p is what makes the encoder accept the stream (confirmed on device:
# configureStreamsPerfLocked ... 1920x1080, then "setupVideoEncoder succeeded").
#
# Do not believe /vendor/etc/media_profiles_V1_0.xml on this point. Its
# VideoEncoderCap for h264 claims maxFrameWidth="3840" maxFrameHeight="2160",
# which is simply wrong -- that element is advisory and only the legacy
# CamcorderProfile path reads it. The CamcorderProfiles in the same file stop at
# quality="1080p", and its own HFR ceiling is 1920x1080.
#
# Everything below is transcribed from the HAL's own parameter dump, read out
# of both cameras with GST_DEBUG=droidcamsrc:9 -- picture-size-values,
# preview-size-values, flash-mode-values, focus-mode-values, whitebalance-values
# and the exposure-compensation range. Stills are left at the sensor's full
# resolution; only video and the viewfinder are capped.
#
# Value lists are Qt enums, not strings:
#   flashValues          QCameraExposure::FlashMode -- Auto 1, Off 2, On 4, Torch 32
#   whiteBalanceValues   QCameraImageProcessing::WhiteBalanceMode -- Auto 0,
#                        Sunlight 2, Cloudy 3, Shade 4, Tungsten 5, Fluorescent 6
#   focusDistanceValues  QCameraFocus::FocusMode -- Infinity 4, Auto 8,
#                        Continuous 16, Macro 32
#
# Omissions are deliberate. There is no iso-values key in either HAL dump, so
# no isoValues is published. The front camera reports focus-mode-values=fixed
# and max-num-focus-areas=0, so it gets no focus keys, and it has no
# flash-mode-values at all, hence the empty flashValues ("@ai []" is the
# GVariant empty-array-of-int32 literal -- a bare [] has no type and dconf
# rejects it).
